{% elif sec == 'server' %} {# ── 1. the server ─────────────────────────────────────────────────── #}
The server {{ endpoint }}

Off on a new installation. While it is off, a client is told there is no MCP here rather than being refused.

why it is off by default An installation that never wanted this should not advertise an endpoint — so it answers 404 rather than 403. Turning it on grants nobody anything: a person still needs a token of their own and the MCP access area, and every answer is filtered by the rest of their areas.

One switch for every change — hosts, playbooks, VMs, Terraform, certificates, GitOps, clusters. With it off, a client can still read everything and troubleshoot.

what it does not waive A token still has to be scoped for changes; the person still needs the area each action demands (a playbook needs Ansible: run, Terraform needs Terraform: apply, a cluster needs Cluster management); a cluster still needs its own management tick; and anything marked production still wants its name typed. Settings, accounts and roles are never reachable over MCP at all.

How many rows a query returns before it is cut. The true total is always reported, so a model knows it is looking at part of the answer. A client may ask for more, up to 500.

days

The expiry offered by default when a token is minted. 0 pre-selects a lifetime token — available because some installations have no way to rotate one, and not the default because a token is a door past two-factor authentication.
