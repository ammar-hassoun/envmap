{# One object's YAML, editable, in a window over the page. WHY A WINDOW Same reason as the log and describe windows: you are looking at one thing out of a list of a hundred, and a navigation costs you the list, the namespace filter and your place in it. WHY THERE IS A CHECK BUTTON AND NOT JUST A SAVE This is the most powerful thing in the product. Every other write is a fixed verb on a named object — restart that, scale this to three — and an applied document can do anything the API server allows, typed by hand. `--dry-run=server` runs the whole admission path and changes nothing, so a typo is a message rather than an outage. It is offered first and costs one click; the apply is deliberately the second button, not the default. The identity guard lives on the server (kmanage.apply_yaml): the submitted document has to still be the object the editor was opened on. The button says "edit this deployment", not "apply arbitrary YAML to my cluster", and without that check those are the same feature. #}
