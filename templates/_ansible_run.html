{# Starting a run, and watching it, in one window over the page. WHY ONE WINDOW AND NOT TWO PAGES Starting a playbook and watching it are the same moment. A form that posted and navigated to a run page would take you off the list you were working from, and — worse — the thing you most want while a run is going is the list of what else is going. WHY IT POLLS AND DOES NOT STREAM The pod-log window holds a socket open because a log has no end. A run does: it prints, it stops, and it means something by its exit code. So this asks for "whatever you have printed since byte N" every second and stops asking when the run says it is done. No socket to keep alive through a proxy, no reconnect logic, and a run whose portal restarted is simply a run that answers `done` — which is exactly what happened to it. THE ORDER OF THE TWO BUTTONS IS THE SAFETY FEATURE Check is first and is the default. Apply — "run for real" — is second, is styled as the dangerous thing it is, carries a confirm, and on a group marked production additionally needs that group's name typed. The same shape as the cluster YAML editor, for the same reason. #}
